# D-002 - Bare `wrsrcli api` reports whether a key is stored, without echoing it

- **Decided:** 2026-09-19 23:24

## Issue

`SPEC.md` §3 defines two forms of the `api` subcommand: `api {key}` to
store a key, and `api -r` / `api --remove` to clear it. It does not say
what bare `wrsrcli api` (no key, no flag) should do.

Phase 1's verify step in `EXECUTION-PLAN.md` needs one: *"`wrsrcli api
{key}` then re-running `wrsrcli api` (or an inspection command) shows the
key is stored."* So some inspection path is required to verify the phase,
but its form was left to the implementer.

Tradeoffs considered:

1. **Error out on bare `api`.** Strictly faithful to the spec's two
   documented forms, but leaves Phase 1 with no way to satisfy its own
   verify step, and makes `api` the only path-like command with no way to
   see current state (`path` with no flags already prints its config).
2. **Print the stored key.** Most direct confirmation, and it is the
   user's own key on their own terminal. Rejected: terminal output lands
   in scrollback, screen shares and pasted bug reports, and `AGENTS.md`
   treats the key as something to keep out of anywhere it could leak. The
   verify step only needs to know *that* a key is stored.
3. **Print a masked form** (e.g. last four characters). Helps identify
   *which* key is stored when a user has several. Rejected for v1 as
   unnecessary — nothing in the spec suggests users juggle multiple keys,
   and it still discloses key material for no required benefit.

## Decision

Bare `wrsrcli api` prints whether a key is stored and nothing about its
value:

- stored: `A Steam Web API key is stored.`
- not stored: `No Steam Web API key is stored.`

The key value is never echoed back by any command. Exit code is 0 in both
cases — this is an inspection, not a check that can fail.

`api --remove` combined with a key argument is rejected as a usage error,
since the two forms are mutually exclusive in the spec.

This is an addition to `SPEC.md` §3's documented interface. §3 should be
updated to list the bare form alongside `api {key}` and `api -r`. Flagged
rather than silently absorbed, per `AGENTS.md`.
