# D-003 - `manifest.json` is written to `%APPDATA%\wrsrcli\`

- **Decided:** 2026-09-19 23:40

## Issue

`SPEC.md` §4.1 leaves the output location of `manifest.json` undecided —
open item #3, *"likely `%APPDATA%\wrsrcli\` or a user-specified output
path; not yet decided"*. `EXECUTION-PLAN.md` Phase 3 requires it resolved
before writing that phase's code, since `scan` cannot write the file
without it and `output-table` must know where to read it from.

Tradeoffs considered:

1. **`%APPDATA%\wrsrcli\manifest.json`.** Keeps all tool state in the one
   place `SPEC.md` §3 already designates, alongside `config.json` and
   `backups\`. `scan` takes no argument and `output-table` finds the file
   with no argument, so the two commands need no shared configuration.
2. **`%APPDATA%` default plus a `--output` flag.** Same default, with the
   option to write a copy elsewhere. Rejected for v1: it forces a matching
   `--input` on `output-table` or leaves copies that command can never
   read, which is configurability nobody asked for (`AGENTS.md`,
   Simplicity first).
3. **Documents folder.** Visible, and consistent with where
   `output-table` offers to save its HTML. Rejected: the HTML is a
   deliverable the user keeps, whereas `manifest.json` is tool state, and
   §3 deliberately keeps tool state out of user-facing folders.

## Decision

Open item #3 is closed. `wrsrcli scan` writes to
`%APPDATA%\wrsrcli\manifest.json`, resolved by the same `config_dir()`
helper that locates `config.json`. Neither `scan` nor `output-table` takes
a path argument for it in v1.

`SPEC.md` §4.1 and §6 item 3 updated to record this.
