# D-004 - Manifest date fields renamed to `date_updated` / `date_touched`

- **Decided:** 2026-09-19 23:40

## Issue

`SPEC.md` §4.1's manifest schema names two date fields `date_created` and
`date_modified`, and sources them from the `.acf`'s `timeupdated` and
`timetouched` in `WorkshopItemDetails`.

`date_created` is a misnomer. `timeupdated` is when the workshop item was
last *updated* by its author; it says nothing about when the item was
created. No creation date exists in any local data source — the workshop
item's posted date comes from the Steam Web API
(`GetPublishedFileDetails`), which is Phase 5 and only available when a key
is set.

Left as written, a value meaning "last updated" would be stored under a
field named "created" and then flow into `output-table`'s **Posted date**
column (§4.2), presenting an update date to the user as a posted date.

Tradeoffs considered:

1. **Rename to `date_updated` / `date_touched`.** Fields state what the
   data is. Costs a small `SPEC.md` §4.1 edit. The manifest carries no
   creation date at all, which is accurate — there isn't one locally.
2. **Keep the spec's names, document the caveat.** No spec change, and
   faithful to §4.1 as written. Rejected: the misnomer survives into the
   rendered HTML, where a user has no way to know the Posted column is
   really an update date.
3. **Keep the names, leave `date_created` null until Phase 5 fills it from
   the API.** Most accurate end state, but leaves the manifest
   structurally incomplete in the no-API path, which §4.2 treats as a
   fully supported mode rather than a degraded one.

## Decision

The `scan` manifest schema uses:

| Field          | Source (`WorkshopItemDetails`) | Meaning                        |
| -------------- | ------------------------------ | ------------------------------ |
| `date_updated` | `timeupdated`                  | item last updated by its author |
| `date_touched` | `timetouched`                  | last touched by Steam locally   |

Both are stored as the raw Unix timestamp strings the `.acf` holds; any
formatting is a presentation concern for `output-table`.

No `date_created` field exists in the manifest. When Phase 5 adds Web API
enrichment, the real posted date (`time_created`) becomes available and
`output-table`'s Posted column is populated from it — in the no-API path
that column has no local source and must be shown as unavailable rather
than filled with `date_updated`.

`SPEC.md` §4.1 updated to match.

## Superseded

Not superseded.
