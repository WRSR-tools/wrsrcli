# D-005 - Items with no `workshopconfig.ini` are included in the manifest, with a warning

- **Decided:** 2026-09-19 23:40

## Issue

`SPEC.md` §2.2 states that each downloaded workshop item's folder contains
a `workshopconfig.ini`. While verifying Phase 2 against the real workshop
folder, one of the 21 installed items did not:

- `3780813529` is listed in **both** `.acf` blocks
  (`WorkshopItemsInstalled` and `WorkshopItemDetails`), so Steam considers
  it installed.
- Its content folder holds only `previewimage.png` — no
  `workshopconfig.ini` and no item content.

`scan` sources `owner_id` and `item_type` from `workshopconfig.ini`, so it
needs a defined behavior for this case before Phase 3 can be written.

Confirmed with the project owner: `workshopconfig.ini` ships in every
workshop download, so this state only arises if the file has been deleted
locally. It is an edge case, not a normal condition — but it is real, and
it is present on the dev machine today.

Tradeoffs considered:

1. **Include the entry with null fields, and warn.** The manifest stays a
   faithful record of what Steam reports as installed. The user is told
   which item is affected and can resubscribe or verify it.
2. **Skip the item, but warn.** Keeps every manifest row fully described,
   so `output-table` never renders a half-empty row. Rejected: the item
   silently disappears from the inventory, and surfacing exactly this kind
   of discrepancy is what an inventory tool is for.
3. **Skip silently.** Rejected outright — an item vanishing from the
   inventory with no trace is the worst outcome for a tool whose job is
   documenting what is installed.
4. **Fail the scan.** Rejected as disproportionate: one damaged item would
   block inventorying the other twenty.

## Decision

`scan` includes every item the `.acf` reports as installed. Where
`workshopconfig.ini` is absent or unreadable:

- `owner_id` and `item_type` are written as `null`.
- The `.acf`-derived fields (`item_id`, `date_updated`, `date_touched`)
  are still populated, since they do not depend on that file.
- A warning naming the item is printed to stderr, e.g.
  `warning: 3780813529 has no workshopconfig.ini (listed as installed in
  the .acf) — owner_id and item_type left null`.
- The scan's exit code is unaffected; this is a reported anomaly, not a
  failure.

`SPEC.md` §2.2's "each downloaded item's folder contains a
workshopconfig.ini" should be softened to note that a locally deleted file
produces this case, and §4.1 should record that the two affected fields
are nullable.

## Superseded

Not superseded.
