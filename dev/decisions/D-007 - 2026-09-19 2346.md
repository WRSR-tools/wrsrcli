# D-007 - A Steam Web API failure degrades `output-table` to local data, not an error

- **Decided:** 2026-09-19 23:46

## Issue

`SPEC.md` §4.2 describes two paths for `output-table`: no key stored
(build from local data, after printing the verbatim notice) and key stored
(additionally query `GetPublishedFileDetails` and `GetPlayerSummaries`).

It does not say what happens when a key *is* stored but the calls fail —
no network, Valve down, a rate limit, or a key that has since been revoked.

Tradeoffs considered:

1. **Warn and fall back to the local-only table.** The user still gets a
   complete, usable inventory of all their items; only the three
   API-sourced columns are missing. The warning names the failure so the
   cause is not hidden.
2. **Abort with an error.** Simple and unambiguous, and guarantees that a
   file, once written, always matches the mode the user expected. Rejected:
   it makes a transient network failure block a command whose primary
   output — the local inventory — needs no network at all.
3. **Write the API columns empty.** Rejected: a table with an Author column
   that is blank on every row invites the reader to conclude the data does
   not exist, rather than that the lookup failed.

## Decision

When a key is stored and the Web API calls fail, `output-table`:

- prints the specific failure to stderr, followed by a second warning
  stating that the table will omit author name, posted date and file size;
- renders the no-API column set (decision recorded in `SPEC.md` §4.2);
- exits 0, because the command produced the output it promised minus the
  enrichment.

A partial success is treated as success: if the API returns details for
only some items, the remaining rows show `—` in the enriched columns
rather than triggering a fallback for the whole table.

The API key is never printed, logged, or included in an error message.
`GetPlayerSummaries` carries the key in its query string, so errors raised
from `steamapi` name only the endpoint, never the request URL.

## Superseded

Not superseded.
