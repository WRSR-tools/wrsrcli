# D-008 - `steamcmd --install` takes an alternate path via `-p` / `--path`

- **Decided:** 2026-09-19 23:48

## Issue

`SPEC.md` §3 says SteamCMD installs to `[STEAMPATH]/steamcmd` by default,
"with an option to choose another path (mechanism for specifying an
alternate path: **OPEN** — likely an additional flag, not yet named)".
This is open item #4, and `EXECUTION-PLAN.md` Phase 6 requires it resolved
before that phase's code is written.

It is also needed immediately for Phase 6's own verify step, which
installs to a throwaway path so the existing SteamCMD at the default
location is left untouched.

Two sub-questions had to be settled together:

**The flag name.** Options were a positional argument
(`wrsrcli steamcmd --install "D:\steamcmd"`), or a named flag. A
positional reads oddly against a command whose action is itself a flag,
and would be ambiguous if `steamcmd` ever gains other verbs. `-p` /
`--path` matches the existing `path` subcommand's `-g`/`-w` short-plus-long
convention.

**What counts as confirmation.** `SPEC.md` §3 specifies the prompt text
and says "On ENTER" the download proceeds, but does not say what other
input means. Treating any input as consent would let a stray keystroke
trigger a download-and-execute; requiring exactly ENTER is the
conservative reading of a prompt whose whole purpose is to gate that
action.

## Decision

Open item #4 is closed.

- `wrsrcli steamcmd -i` / `--install` installs to `[STEAMPATH]/steamcmd`.
- `wrsrcli steamcmd -i -p "{path}"` / `--path "{path}"` installs to
  `{path}` instead. The directory is created if absent.
- `steamcmd` with no `--install` prints usage and exits non-zero; `-p`
  without `-i` is a usage error, since it modifies an action rather than
  being one.

At the confirmation prompt, **only an empty line (ENTER) proceeds.** Any
other input cancels, prints `Cancelled — nothing was downloaded.`, and
exits 0 (the user's choice is not a failure). This keeps the one place
that downloads and runs third-party code behind an unambiguous,
affirmative gate, per `AGENTS.md`'s security rules.

`SPEC.md` §3 and §6 item 4 updated.
