# D-009 - Backup storage layout, and the multi-version restore/rollback prompt

- **Decided:** 2026-09-19 23:52

## Issue

Two things had to be settled before Phase 8 could be written.

**1. Where backups physically live.** `SPEC.md` §3 places the backup
manifest in `%APPDATA%\wrsrcli\`, and §5 places removed files in
`%APPDATA%\wrsrcli\backups\`. §5's per-entry schema requires a
`backup_path`, but the naming scheme inside that folder was never
specified.

Mirroring each original's full path under the backup root would be
human-browsable, but game and workshop paths are already deep, and
Windows' default 260-character path limit makes silent failure on long
paths a real risk — in a subsystem whose entire purpose is not losing
files.

**2. The multi-version prompt.** Open item #5: the wording and UI for
choosing between backup generations, used by both `restore` (this steamid
as destination, hit by multiple origins) and `rollback` (this steamid as
origin, imported several times). `SPEC.md` §5 marks it OPEN.

## Decision

**Storage layout.** Backups are grouped by origin item and by *run*, where
one run is one execution of `wrsrcli import` and therefore one generation:

```
%APPDATA%\wrsrcli\backups.json                  <- the manifest
%APPDATA%\wrsrcli\backups\{origin}\{YYYYMMDD-HHMMSS}\{nnn}_{filename}
```

`{nnn}` is a zero-padded counter within the run, making names unique
without reproducing deep source paths. The original location is not
encoded in the backup path at all — it is recorded in the manifest's
`original_path`, which is the field `restore` and `rollback` actually read.
This keeps backup paths short and collision-free regardless of how deep the
original sat.

A `remove` moves the file into the backup (never deletes). A `copy` that
would overwrite an existing file copies the existing file into the backup
first, then overwrites. Both are logged before the destructive step, per
§5 and `AGENTS.md`'s hard-delete prohibition.

**Multi-version prompt.** Open item #5 is closed with this wording, used
by both commands (`{n}` generations, newest first):

```
3 backup versions found for 3780739284. Select which to restore:
   1. 2026-09-19 23:52 - from 3621284903 - 4 file(s)
   2. 2026-09-18 21:10 - from 3773771138 - 1 file(s)
   3. 2026-09-17 09:33 - from 3621284903 - 12 file(s)

Please select (or press ENTER to cancel):
```

- The verb matches the command: "Select which to restore" for `restore`,
  "Select which to roll back" for `rollback`.
- Each line carries the generation's timestamp, the *other* party in the
  relationship (the origin that caused the change for `restore`; the
  destination that was affected for `rollback`), and the file count, since
  those are what distinguish otherwise-identical generations.
- ENTER cancels and changes nothing — consistent with D-008's rule that
  the destructive path needs affirmative input.
- An out-of-range or non-numeric answer re-prompts rather than aborting.

Where only one generation exists, no prompt is shown and it is acted on
directly, per §4.4/§4.5.

`SPEC.md` §5 and §6 item 5 updated.
