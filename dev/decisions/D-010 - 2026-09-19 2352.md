# D-010 - How overlapping `copy` entries are surfaced to the user

- **Decided:** 2026-09-19 23:52

## Issue

`SPEC.md` §4.3 says of `copy`:

> Conflict/overwrite order when multiple `copy` entries (e.g. `*` and a
> specific named file) target overlapping destinations: Surface to user,
> present selectable options with dates the change occured.

This settles the *policy* — ask, don't pick silently — but leaves the
mechanics open: what counts as an overlap, what the options are, and which
dates are meant.

The ambiguity is "dates the change occured". Within a single `import` run
no change has occurred yet, so it cannot mean the destination's history.
Read against the example (`*` versus a specific named file), the
distinguishing information between two candidates is the **source files**:
the same destination path can be reached from two different files inside
the origin item's folder, and their modification times are what tell them
apart.

## Decision

An overlap is detected when two or more `copy` entries in one import list
resolve to the **same destination file path** from **different source
files**. Detection happens after all entries are expanded (so `*` and
directory sources are resolved to concrete files) and before any file is
written, so nothing is copied until every conflict is settled.

Two entries resolving the same destination from the *same* source file are
not a conflict; the duplicate is dropped silently.

For each conflict the user is prompted:

```
Conflict: 2 sources map to [GAME]/media_soviet/signs/signscript.txt
   1. signscript.txt              - modified 2026-08-14 11:02
   2. extras/signscript.txt       - modified 2026-09-01 16:47

Please select which to copy (or press ENTER to skip this file):
```

- Sources are listed in the order their entries appear in the import list.
- The date shown is the source file's filesystem modification time.
- ENTER skips that destination entirely — neither source is copied, and
  nothing at the destination is touched or backed up.
- An out-of-range or non-numeric answer re-prompts.

Resolution is per destination file, not per entry: a `*` entry may win
some files and lose others, which is what the spec's own example implies.

`SPEC.md` §4.3 updated to record the mechanics.
