# D-011 - Import lists are registered and copied, so `manual-rerun` has something to replay

- **Decided:** 2026-09-19 23:54

## Issue

`SPEC.md` §4.6 defines `manual-rerun` as re-executing "the `copy`/`remove`
operations of all previously-run import lists currently tracked". But
nothing in the spec tracks them.

§5's backup manifest records `origin_steamid`, `destination`, `action`,
`original_path`, `backup_path` and `timestamp`. That is enough to *undo* an
import — which is what `restore` and `rollback` do — but not to *repeat*
one:

- A `copy` entry records the file that was overwritten, not the source it
  was overwritten from. The origin-relative `src` is nowhere in the
  manifest.
- An import that overwrites nothing produces no backup entries at all, so
  it would leave no trace to replay.
- The import list is a user-authored file at an arbitrary path, which may
  have been moved, edited or deleted since the import ran.

So §4.6 requires state that §5 does not provide. This has to be recorded
somewhere new.

Tradeoffs considered:

1. **Register the import list's path only.** Minimal addition. Rejected:
   replay then breaks whenever the user moves or edits the file, and a
   rerun that silently applies a *different* list than the one originally
   imported is worse than no rerun at all.
2. **Store a copy of the import list, plus a registry entry.** The replay
   is guaranteed to be the operations that actually ran. Costs one small
   YAML copy per import.
3. **Extend the backup manifest with source paths.** Keeps everything in
   one file, but bloats a schema the spec defines explicitly, and still
   fails for imports that back nothing up.

## Decision

Each `import` run registers itself:

```
%APPDATA%\wrsrcli\imports.json               <- the registry
%APPDATA%\wrsrcli\imports\{origin}\{stamp}.yaml  <- verbatim copy of the list
```

A registry entry records `origin_steamid`, the run `stamp` (shared with the
backup generation), the original `list_path` as given by the user, the
`stored_list` copy, and a `timestamp`. Registration happens even when the
import backed nothing up, so every run is replayable.

`manual-rerun` replays **the most recent registered list per origin item**.
Re-running every historical generation would re-apply superseded versions
of a list in arbitrary order; the newest registration is the state the user
last chose for that origin. Replay goes through the same planning, conflict
resolution and backup-before-write path as a first-time import — a rerun is
an import, not a privileged operation.

`SPEC.md` §4.6 updated to record where the tracked lists live.

Not superseded.
