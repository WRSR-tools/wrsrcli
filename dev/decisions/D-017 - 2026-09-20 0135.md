# D-017 - Bare `wrsrcli` prints help, rust becomes the table accent, and `open-web`

- **Decided:** 2026-09-20 01:35

## Issue

Four changes requested together once B-001 was confirmed fixed. Two are
straightforward; two involve a call worth recording.

1. `wrsrcli` with no arguments should print the help rather than argparse's
   usage error.
2. The HTML table's accent colour should become the rusty red.
3. In the first-run prompt, only `ENTER` should be coloured, not the whole
   line.
4. A new `open-web` command should open the project website.

## Decision

### 1. Bare `wrsrcli` prints help — and exits 0

`argparse` was producing

```
usage: wrsrcli [-h] [--version] <command> ...
wrsrcli: error: the following arguments are required: <command>
```

which answers "what is this?" with a complaint. The help is the better
answer, and it is what someone typing the bare name is asking for.

**The recorded call is the exit code.** It was 2; it is now 0. Printing the
help because the user asked for it is not a failure, and `wrsrcli --help`
already exits 0, so the two paths now agree. The cost is that a script doing
`wrsrcli || handle_error` no longer detects a missing subcommand — but no
such script can exist yet, the tool is unreleased, and the alternative
(printing help while claiming failure) is the more confusing of the two.

An unrecognised or malformed subcommand still goes through argparse and
still exits 2. Only the no-arguments case changed.

This sits *after* the first-run branch in `cli.main`, so a double-clicked
executable still gets the installer rather than a wall of help text.

### 2. Rust as the table accent

`--accent` moves from `#7a1f1f` to `#b7410e` in light mode, and from
`#c96a6a` to `#d9793f` in dark, matching the console's rust (D-016).

Contrast was checked rather than assumed, because the accent is used for
focus outlines and the sorted-column header — both load-bearing:

| | before | after |
|---|---|---|
| light, on `#f6f6f4` | 9.50:1 | 5.14:1 |
| dark, on `#17171a` | 4.90:1 | 5.76:1 |

Light mode loses a good deal of headroom and still clears WCAG AA for normal
text (4.5:1). Dark mode improves. Accepted: the colour is decorative plus a
sort indicator that is also marked with an arrow glyph and `aria-sort`, so no
information depends on the colour alone.

### 3. Only the key name is coloured

`Press ENTER to install...` splits into three parts, with rust on `ENTER`
only. This narrows D-016, which coloured the whole prompt line.

The request was for the remainder to be "white". It is left *uncoloured*
instead, which renders as white on a dark console — the same result on the
reporter's machine — but does not force white onto a light-background
terminal, where explicit white on white would be unreadable. Emitting no
colour is the only version of "white" that is safe on both, and the rest of
the screen is already uncoloured, so the prompt now matches it.

### 4. `open-web`

`webbrowser.open` from the stdlib, on `https://wrsr-tools.github.io/`. The
URL is printed before opening, so it is still usable when no browser can be
launched, and a `False` return is reported as an error naming the URL.

The site is still unpublished (noted in D-016). This command now points at
it as well as the first-run screen, so there are two places that break until
it exists.

## Superseded

Not superseded. Narrows D-016's colour placement; does not replace it.
