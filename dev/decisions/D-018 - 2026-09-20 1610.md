# D-018 - WMLS v1: versioned markup, multi-item lists, and dependencies

- **Decided:** 2026-09-20 16:10

## Issue

`dev/wmls/standard.v1.md` replaces `standard.beta.md` as the import-list
markup wrsrcli should parse. Three things change, and each raises a
question the standard does not answer on its own:

1. Files now declare `version: 1` on the first line, and items live under
   an `items:` list rather than at the top level. What happens to the
   `beta` files already in circulation — and to the verbatim copies
   `manual-rerun` replays from `%APPDATA%\wrsrcli\imports\`?
2. A list can describe several items. Backups, history and `manual-rerun`
   are all keyed on a single origin ID per run, so "one list" is no longer
   "one run".
3. `depends-mandatory:`/`depends-optional:` cause downloads. AGENTS.md
   requires downloads to be opted into explicitly, and `_ensure_origin_present`
   already downloads the origin without asking.

## Decision

### 1. Both markups are parsed; `beta` warns

`version` absent means `beta` — a single top-level `item:`, no
dependencies. It is parsed and applied exactly as before, with a warning
on stderr naming the file and what to change. The standard says each
version supports the one before it, and dropping `beta` outright would
break every stored list in `imports/` the moment a user upgraded, with
`manual-rerun` the thing that failed rather than the thing they ran.

`version: 1` requires `items:`. Any other `version:` value is an error
rather than a best-effort parse — a file written to a future WMLS may use
keys this build would silently ignore, and ignoring a `remove:` it does
not understand is the failure mode worth preventing.

The two shapes are also checked against each other: `items:` without
`version:`, and `item:` under `version: 1`, each get the specific error
rather than the generic "no item" one.

Rejected: converting stored `beta` copies to v1 on read. It would rewrite
a record whose whole value is being verbatim.

### 2. One item is one run, not one list

Each entry in `items:` gets its own `backup.Run` and its own
`history.register`, keyed on that item. `restore`, `rollback` and
`manual-check` are untouched as a result — they still see one origin per
generation, and a multi-item list is indistinguishable from the same items
imported separately.

The consequence is in `manual-rerun`. `latest_per_origin` returns one entry
per origin, and a three-item list produces three entries all pointing at
the same stored file. Replaying the whole file for each would apply every
item three times. So `_apply` takes an `only=` origin, and a rerun passes
the origin it tracked: each entry replays exactly its own item. A stored
list that no longer describes the tracked origin is warned about and
skipped rather than aborting the remaining reruns.

Duplicate `item:` entries within one file are rejected at parse time.
Allowing them would give one origin two generations in a single run, the
second masking the first in `latest_per_origin`'s view.

### 3. Mandatory downloads silently, optional asks

Mandatory dependencies are downloaded without a prompt. They are the same
category as the origin item itself — the import cannot do its job without
them — and the origin already downloads unprompted, so prompting for one
and not the other would be arbitrary. A failure aborts that item.

Optional dependencies are offered one at a time, with the list author's
`message` printed above the prompt. ENTER accepts and anything else skips,
matching `steamcmd --install` and the first-run screen (D-008, D-017)
rather than introducing a third prompt idiom. `message` is therefore
mandatory on an optional dependency: it is the only thing the user has to
decide on, and a missing one would leave them choosing about a bare ID.

Both kinds are resolved before the item's own `copy:`/`remove:` run, and
anything already present in the workshop folder is skipped without output.

Dependencies are downloaded only. Nothing is applied on their behalf — a
dependency with its own import list is its own list, and inferring one
would mean acting on files the author of *this* list never named.

### 4. `*` is not a glob

The standard states `*` means the origin item's root folder and is not a
wildcard inside a path. `src: "signs/*"` is now a parse error naming the
trailing-slash form instead. Previously it was treated as a literal path,
so it failed later with "not found in {folder}" — technically a refusal,
but one that reads like the file is missing rather than like the markup is
wrong.

### 5. Hyphenated dependency keys

WMLS v1 spells these `depends-mandatory:`/`depends-optional:`. The `beta`
document's roadmap section used underscores. A file using the underscored
spelling is an error naming the hyphenated one, rather than a file whose
dependencies are silently ignored because the key did not match.
