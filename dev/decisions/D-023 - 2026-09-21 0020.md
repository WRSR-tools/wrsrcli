# D-023 - Bundling Valve's Steamworks redistributable

- **Decided:** 2026-09-21 00:20

## Issue

Subscribing is the only operation that leaves Steam's own records correct:
it writes the `.acf` entry, so `scan` sees the item like any other and
`latest_timeupdated` keeps working. Everything D-021 and D-022 built around
sideloading exists because the tool could not subscribe.

It can. `ISteamUGC::SubscribeItem` was called against the running client
from Python via `ctypes`, and item 3773169177 went from "not tracked" to
"subscribed, installed" in 2.5 seconds, appearing in the `.acf` with the
correct `subscribedby`. That needs Valve's `steam_api64.dll`, which raises
where the file comes from and under what terms it travels.

## Decision

### 1. The library is bundled, not fetched

Three shapes were weighed.

**A separate repository** that `install` downloads from was the initial
plan, on the theory that separating the binary from the code separates the
licences. Reading the grant defeats it. Section 1.1(b) of the Steamworks
SDK Access Agreement permits reproducing and distributing the contents of
`redistributable_bin` *along with the Licensee Software*. A standalone repo
serves the library on its own, to anyone, whether or not they have wrsrcli
— which is not the case the grant describes, and section 1.3 reserves
every right not expressly granted, leaving nothing to imply one from. The
separation intended to improve the licensing position weakens it.

**Requiring each user to supply their own SDK** relies on no grant at all:
each user accepts the agreement themselves. It was rejected on friction,
not principle. It asks someone who wants a bus mod to sign in to a partner
site and enter a contract with Valve, and a fair number would reasonably
stop there.

**Bundling** is the case section 1.1(b) actually describes: Valve's
redistributable, in object code, travelling with the software built against
it. It is also the least friction, since the file simply arrives with the
tool.

### 2. Through the SDK, never around it

Section 2.4 forbids reverse engineering and requires that software
interacting with Steamworks Services do so through the API provided by the
SDK Redistributables, rather than communicating with those services
directly. An earlier idea — driving `steamclient64.dll` in the Steam
install, which every user already has and which would need nothing shipped
— is exactly what that clause describes. It is not taken, and this decision
records that it was considered and why it was not.

That the game's own `steam_api64.dll` cannot serve either is a matter of
fact rather than terms: WRSR ships an SDK-era shim (`SteamClient017/018`)
whose accessor cannot reach a modern `SteamClient023`, and the versions
shipped by other games vary machine to machine. Depending on whatever
happens to be installed would fail differently for each user.

### 3. The licence carve-out, and where it lives

`LICENSE` is left byte-identical. Editing a standard licence's text
produces a non-standard licence and defeats automated identification; the
carve-out belongs beside it, not inside it.

- `NOTICE` carries it, because Apache-2.0 section 4(d) obliges derivative
  works to reproduce NOTICE contents. The carve-out therefore propagates to
  forks without depending on anyone reading the README.
- `THIRD-PARTY-NOTICES.md` records the file, SDK version, size, SHA-256,
  Valve's copyright and the agreement's URL, plus what a forker's position
  actually is.
- The agreement's own text is **linked, not reproduced**. Valve's
  documentation page carries a restricted-access banner asserting
  confidentiality, and there is no need to copy it to cite it.
- `pyproject.toml` keeps `license = "Apache-2.0"`, which describes
  wrsrcli's own code, with a comment and `license-files` pointing at the
  exception. No SPDX expression describes "Apache-2.0 plus one
  proprietary binary", so the metadata states the project's licence and the
  files state the exception.

A fork's right to redistribute the library rests on its own acceptance of
the agreement — section 6.2 bars assignment, and the Apache grant cannot
convey what this project does not own. Deleting the file is a supported
configuration, which is why every feature degrades rather than breaks.

### 4. The pinned hash is a security control, not bookkeeping

`steamworks.py` refuses to load a library whose SHA-256 is not the one
shipped. This is native code loaded by `ctypes` into a process holding the
user's Steam session and acting on their account; a substituted DLL is
arbitrary code execution with that reach. A mismatch is a refusal naming
both digests, never a warning.

### 5. Nothing initialises at import

`SteamAPI_InitFlat` binds the whole process to app 784150 and starts a
callback pump, so it happens once per run, lazily, on first use — never at
startup, where most commands would pay for something they never touch.
`connect()` returns a reason rather than raising, because every caller has
something useful to do without it.

## Superseded

Not superseded. D-021's SteamCMD path and D-022's staleness sources remain
correct and stay in use where subscribing is unavailable.
