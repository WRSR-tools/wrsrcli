# D-024 - Steam replaces SteamCMD and the Web API

- **Decided:** 2026-09-21 01:10

## Issue

SteamCMD existed in this tool for one reason: to get workshop items onto
disk. It was never a good way to do it. Items it fetched had no `.acf`
entry, so Steam neither updated them nor knew they existed, and D-021 had to
invent `downloads.json` and folder-on-disk scanning to keep track of what
Steam refused to record.

D-023 established that `ISteamUGC::SubscribeItem` works. A subscription
installs the item *and* keeps it updated, and Steam writes the `.acf` entry
itself. That makes the sideloading machinery obsolete rather than merely
improvable.

The same library answers the metadata question. `SteamUGCDetails_t` carries
the title, owner, published and updated times and the item's required items;
`ISteamFriends` resolves an owner id to a display name; `GetItemInstallInfo`
gives size on disk. Between them they supply everything the Steam Web API
was queried for, without a key.

## Decision

### 1. SteamCMD is removed

`steamcmd.py`, the `steamcmd` verb, its install prompt and
`_fetch_into_workshop` are gone, along with `downloads.json` and the
`date_latest`-recording machinery that existed to compensate for Steam's
ignorance of sideloaded items.

`update` subscribes. `import` subscribes when an origin item or a declared
dependency is missing. Both then wait for Steam to report the item
installed, because subscribing is acknowledged immediately and downloaded
afterwards — reporting success on the call alone would claim an install that
has not happened, and `import` is about to copy files out of that folder.

The backup-before-replace path goes with it. Nothing overwrites an existing
item any more; Steam updates its own content in place.

### 2. The Steam Web API is removed

`steamapi.py`, the `api` verb, the stored key and the no-key message are
gone, and with them the entire two-mode table: there is no longer a reduced
rendering for users without a key, because there are no users without a key.

The consequence is that `scan` now needs Steam running, where it previously
needed only the disk. That is accepted. `scan` is the command that talks to
Steam, and it writes what it learns into the manifest — titles, authors,
published dates, sizes and dependencies — so `output-table` renders from the
manifest alone and works with Steam closed and no network at all. The
division is cleaner than the one it replaces, where both commands queried.

With Steam closed, `scan` still writes the manifest from the `.acf` and
`workshopconfig.ini`, warns, and omits the enrichment.

A gain worth naming: an item whose `workshopconfig.ini` has been deleted
locally had no name or owner anywhere (D-005). Steam knows both, so those
rows are now populated instead of blank.

### 3. Staleness prefers Steam, falls back to the `.acf`

`GetItemState` reports `NeedsUpdate` directly — Steam's own live answer,
with no timestamps compared. `update` uses it.

`output-table` has no Steam connection, so the accordion keeps D-022's
comparison of `date_updated` against `date_latest`, both captured from the
`.acf` by `scan`. An item that is downloading is not reported stale; it is
already being dealt with.

### 4. A folder Steam does not know about is now always a warning

D-021 §2 added folder-on-disk scanning so that items `update` placed would
be visible. Nothing places files outside Steam any more, so such a folder
was put there by something else. It is still inventoried — it is on disk and
the game will load it — but it is always warned about, naming the
consequence: Steam will never update it.

### 5. Struct decoding is defended, not trusted

`SteamUGCDetails_t` is read at measured offsets rather than computed ones,
because the header's constants and the binary's layout disagree: the owner
id sits at 8160, not the 8152 the declared sizes imply. Every decode is
re-checked — owner within the SteamID64 range, timestamps within plausible
bounds — and a record that fails is dropped rather than believed.

The struct is always written into a 64 KB buffer. An undersized one lets
Steam write past it and takes the process down with no traceback, which was
observed, and is not a failure mode worth risking on arithmetic.

## Superseded

- **D-007** (degrade to a local-only table when the Web API fails): there is
  no Web API call left to fail.
- **D-021 §1 and §3**: downloads no longer go to SteamCMD's folder or
  anywhere else, and `downloads.json` is gone.
- **D-022 §1 and §4** in part: the API is no longer one of the two staleness
  sources. The `.acf` half stands and is now the offline path.
- **D-008** survives in spirit, not in letter: its ENTER-to-proceed prompt
  guarded a download, and `update` now guards a subscription the same way.

D-005's handling of a missing `workshopconfig.ini` is unchanged, but its
consequence is softened — the fields it left null are now filled from Steam
where Steam knows them.
